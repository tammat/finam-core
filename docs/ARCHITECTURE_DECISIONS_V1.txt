============================================================
MAIN GOAL
============================================================

Главная цель проекта:

Автоматический поиск устойчивых прибыльных торговых моделей
с последующей проверкой:

Research
↓

Paper

↓

Shadow

↓

Live

Архитектура не является целью.
Архитектура существует исключительно для достижения данной цели.

============================================================
ARCHITECTURE PRINCIPLES
============================================================

1. DOMAIN FIRST

Database
↓

Repository
↓

Mapper
↓

Provider
↓

Resolver
↓

Domain Service

------------------------------------------------------------

2. IMMUTABLE DTO

Все DTO являются immutable.

Передача dict между сервисами запрещена.

------------------------------------------------------------

3. SQL

SQL разрешен исключительно внутри Repository.

------------------------------------------------------------

4. NO HARDCODE

Запрещено хранить в исходном коде:

- символы
- стратегии
- таймфреймы
- комиссии
- налоги
- Universe
- Broker
- Account Scope

Все значения должны поступать через:

MarketModelResolver

или

Provider.

------------------------------------------------------------

5. MARKET MODEL

Единый источник истины.

MarketSnapshot

↓

Instrument

Contract

TradingCost

Tax

TradingSession

Eligibility

Version

------------------------------------------------------------

6. PROVIDER

Provider не содержит SQL.

Provider не строит DTO.

Provider только координирует:

Repository

↓

Mapper

↓

DTO

------------------------------------------------------------

7. RESOLVER

Любой бизнес-модуль получает данные рынка
исключительно через MarketModelResolver.

Прямой доступ к таблицам market_* запрещен.

------------------------------------------------------------

8. JSON

JSON является транспортным форматом.

JSON никогда не отображается пользователю.

------------------------------------------------------------

9. PRESENTATION

DTO

↓

JSON

↓

ViewModel

↓

UI Component

↓

HTML

------------------------------------------------------------

10. UI

Используются только компоненты:

KPICard

DataTable

TreeView

ObjectCard

ProgressBar

Chart

Section

PageLayout

------------------------------------------------------------

11. I18N

Все пользовательские строки проходят через
единый механизм локализации.

------------------------------------------------------------

12. SNAPSHOT

Каждая сделка должна знать:

Market Model Version

Strategy Version

Parameter Version

Snapshot Time

------------------------------------------------------------

13. VERSIONING

Любое изменение модели рынка
не должно изменять историю.

Используются Snapshot.

UPDATE истории запрещен.

POST FREEZE RULE
============================================================

После ARCHITECTURE_FREEZE_V4
архитектура считается завершенной.

Новые архитектурные компоненты запрещены.

Разрешаются только:

- исправления ошибок;
- устранение технического долга;
- развитие поиска edge;
- развитие Paper / Shadow / Live.
